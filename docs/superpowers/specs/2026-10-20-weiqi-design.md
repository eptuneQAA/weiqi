# 围棋软件设计规格

- 日期：2026-10-20
- 状态：已确认
- 项目路径：`/home/UOS/weiqi`

## 1. 目标与范围

开发一款可离线运行的桌面围棋软件，满足以下需求：

1. 人机对战：内置 AI，三档难度，无需安装第三方引擎。
2. 局域网对战：两名玩家各运行一份程序，一台创建房间，另一台加入；支持手动输入 IP 和 UDP 自动发现两种方式。
3. 棋盘支持 9 路、13 路、19 路。
4. 采用中国规则数子，贴目 7.5，包含提子、禁入点、劫争、停一手、认输、终局数子。
5. 局域网文字聊天：对局期间双方可互发文本消息，消息仅在当前房间内显示，不持久化。

明确不做：互联网对战平台、观战、SGF 存档、让子、计时器、局域网悔棋、断线重连、段位级 AI。

## 2. 技术约束

- 运行环境：Linux（UOS/Deepin），Python 3.7。
- GUI：PyQt5（系统已安装，Qt 5.11），中文界面。
- 第三方依赖：仅 PyQt5；不使用 numpy、第三方围棋库或网络库。
- 测试：Python 内置 `unittest`，不引入 pytest。
- 单进程分层架构：规则、AI、网络、UI 解耦；AI 放入 `QThread`，网络使用 Qt 事件驱动的 `QTcpServer` / `QTcpSocket` / `QUdpSocket`，不阻塞界面。

## 4. 规则引擎

### 4.1 棋盘表示

- 使用 `size x size` 的二维 `list`，`0` 空、`1` 黑、`2` 白。
- 坐标内部统一为 `(x, y)`，左上角为 `(0, 0)`，x 向右、y 向下。
- 棋盘尺寸只允许 9、13、19；星位按各尺寸标准位置绘制。

### 4.2 落子规则

- 落子点必须为空、在棋盘内、当前轮到该颜色。
- 落子后先提掉相邻的无气对方棋组，再检查己方棋组是否有气；无气则为禁入点（禁止自杀）。
- 劫争使用位置超级劫：保存历史局面哈希集合，若落子后的局面在历史中出现过则拒绝。该规则同时覆盖普通劫与三劫循环。
- 提子后更新双方提子数，用于界面展示。

### 4.3 对局状态机

状态：`PLAYING`（对局中）、`SCORING`（数子中）、`FINISHED`（已结束）。

- `play(x, y)`：校验并落子，记录历史，切换执子方。
- `pass()`：记录一次停一手；连续两次 pass 进入 `SCORING`。
- `resign(color)`：该方认输，立即进入 `FINISHED`，对方获胜。
- `undo()`：仅人机模式可用，一次撤销最近两手（AI 一手 + 玩家一手）；若 AI 尚未落子，则只撤销玩家一手。局域网模式不提供。
- 历史记录包含落子、pass 与局面哈希，供悔棋和超级劫使用。

### 4.4 数子

- 中国规则面积计分：`得分 = 己方棋子数 + 己方围住的空点数`。
- 贴目固定 7.5，白方得分加 7.5。
- 连续两次 pass 后进入 `SCORING`：
  - 先自动标记明显死子：按无死子状态做一次领地划分，若某棋组没有真眼，且其所有气都落在对方领地内，则标记为死子。
  - 玩家（人机模式）或主机（局域网模式）可点击棋组切换死活；死子从棋盘移除，其位置按对方领地计算。
  - 确认后计算双方面积，输出“黑胜/白胜 X.5 点”或“和棋”。
- 数子阶段双方均可查看预览分，但只有主机（局域网）或玩家（人机）能修改标记。

## 5. AI 设计

### 5.1 难度

| 难度 | 思考时间上限 | 说明 |
| --- | --- | --- |
| 入门 | 0.3 秒 | 以战术启发式为主，适合新手 |
| 普通 | 1.0 秒 | 启发式 + 浅层 MCTS |
| 较强 | 2.5 秒 | 启发式 + 较深 MCTS，19 路仍受时间上限约束 |

### 5.2 算法

1. 候选点生成：
   - 已有棋子周围距离 2 以内的空点；
   - 开局阶段的星位、角部要点；
   - 过滤自杀点、填自己真眼的点、被超级劫禁止的点；
   - 优先加入可提对方棋组、可救己方被打吃棋组、可打吃的战术点。
2. 评估与搜索：
   - 先做战术检查：能提子、能逃出打吃、避免自打吃。
   - 其余情况使用 UCT MCTS；随机模拟采用“局部偏置”策略，优先在最后一手附近落子，连续无意义落子则 pass，单次模拟最多 200 手。
   - 9/13 路以 MCTS 为主；19 路减少模拟深度、提高启发式权重，保证在时间上限内返回。
3. 输出：返回合法落子或 pass；找不到合法点时 pass。

### 5.3 线程与交互

- AI 在独立 `QThread` 中计算，主线程不阻塞。
- 思考期间界面显示“AI 思考中…”，禁用落子；开始新对局、悔棋或退出时设置取消标志，线程尽快结束。
- AI 异常时回退为随机合法点，并在状态栏提示。

## 6. 局域网设计

### 6.1 角色与权威

- 主机创建房间并持有唯一权威 `GameState`；客机的落子必须经主机校验。
- 客机本地也执行同样规则用于即时反馈，但以主机返回结果为准；被拒绝时回滚显示。
- 一局最多两名玩家；客机只能在开局前加入，开局后拒绝加入。

### 6.2 传输

- TCP，UTF-8 JSON，每行一条消息（`\n` 分隔）。
- 默认 TCP 端口 `45679`；主机端口被占用时提示错误并允许修改端口。
- UDP 发现端口固定 `45678`。
- 协议版本号 `1`；版本不一致时拒绝连接并提示。

### 6.3 消息定义

客机 -> 主机：

- `hello`：`{type, version, name}`，`name` 去除首尾空白后限 1-20 字符
- `move`：`{type, x, y}`
- `pass`：`{type}`
- `resign`：`{type}`
- `mark_dead`：`{type, points: [[x, y], ...]}`，仅主机允许修改，客机端该消息会被拒绝
- `confirm_score`：`{type}`
- `chat`：`{type, text}`，`text` 为去除首尾空白后的纯文本，长度 1-500 字符
- `ping`：`{type}`
- `leave`：`{type}`

主机 -> 客机：

- `welcome`：`{type, version, room, board_size, komi, host_color, guest_color, state}`
- `state`：`{type, moves, turn, captures, phase, score_preview}`，用于同步
- `move_result`：`{type, ok, error, state}`
- `score_preview`：`{type, black_area, white_area, dead_points, phase}`
- `result`：`{type, winner, black_area, white_area, reason}`
- `chat`：`{type, name, text, timestamp}`，主机转发时补充发送者名称与 Unix 毫秒时间戳，客户端按本地时区显示为“时:分”
- `error`：`{type, message}`
- `pong`：`{type}`
- `bye`：`{type, reason}`

`state.moves` 为按顺序的落子列表（`pass` 用 `null` 表示），客机收到后重建局面，避免增量同步歧义。

### 6.4 连接流程

1. 主机创建房间：选择棋盘大小、执黑/执白、房间名；监听 TCP 端口并开始 UDP 广播。
2. 客机加入：自动发现列表或手动输入 IP/端口；发送 `hello`。
3. 主机校验版本与房间状态，回复 `welcome`，对局开始，主机先手或按设定颜色行棋。
4. 每步落子由当前行棋方发送；主机校验后广播 `move_result` 与最新 `state`。
5. 任意阶段双方均可发送 `chat`：客机消息由主机补全名称与时间后转发；主机消息直接发送给客机。聊天不会改变对局状态。
6. 双方连续 pass 后主机进入数子阶段，广播 `score_preview`；主机标记死子并确认，广播 `result`。
7. 任一方认输、断线或离开：对局结束，另一方收到 `bye` 或断线提示。

### 6.5 自动发现

- 主机每 2 秒向 `255.255.255.255:45678` 广播：
  `{"magic": "WEIQI_DISCOVERY", "version": 1, "room": "...", "tcp_port": 45679, "board_size": 19, "host_color": 1}`。
- 客机绑定 UDP `45678` 接收广播，维护房间列表；超过 5 秒未更新的条目移除。
- 端口占用、防火墙拦截或跨网段导致发现失败时，手动输入 IP 仍可连接。
- 同一台机器运行两个实例测试时，允许通过启动参数 `--no-discovery` 关闭自动发现，避免端口冲突。

### 6.6 心跳与异常

- 双方每 5 秒发送 `ping`，15 秒无任何消息视为断线。
- 断线后显示“对手已断开，对局结束”，关闭连接并回到空闲状态。
- 非法 JSON、未知消息、越权操作均回复 `error`，不崩溃；连续非法消息超过 5 条则断开。
- 聊天消息计入断线检测（收到任意合法消息即刷新超时计时）。

## 7. 界面设计

### 7.1 主窗口

- 中央为自绘棋盘，右侧为信息与操作侧栏。
- 侧栏显示：当前模式（人机 / 主机 / 客机）、轮到谁、双方提子数、手数、房间信息（联机时）。
- 按钮：新对局、停一手、认输、悔棋（仅人机）、确认数子（数子阶段）。
- 联机模式下侧栏底部显示聊天面板；人机模式隐藏聊天面板。
- 状态栏显示提示信息，如“AI 思考中…”“等待对手落子”“对手已断开”。

### 7.2 棋盘绘制

- 木纹底色渐变，19/13/9 路网格与标准星位。
- 棋盘外绘制坐标：横轴使用字母 A-T（跳过 I），纵轴使用数字 1-19，随棋盘尺寸截取。
- 棋子使用径向渐变表现立体感；最后一手用红色圆点标记。
- 鼠标悬停显示半透明预览棋子；非本方回合、AI 思考、数子阶段禁用落子。
- 窗口缩放时棋盘保持正方形并自适应。

### 7.3 对话框

- 新对局：模式（人机）、棋盘大小、难度、执黑/执白。
- 创建房间：房间名、棋盘大小、主机执黑/执白、显示本机 IP 与端口。
- 加入房间：自动发现列表（房间名、IP、棋盘大小）、手动 IP/端口输入、刷新按钮。
- 结果：显示胜负、双方面积、结束原因；人机模式提供“再来一局”，联机模式仅提供“关闭”，需重新创建/加入房间。

### 7.4 聊天面板

- 仅联机模式显示，位于右侧栏底部，包含只读消息列表、输入框和“发送”按钮。
- 消息格式：`发送者 时:分` 换行显示正文；自己的消息靠右或使用不同颜色，系统消息（加入、离开、断线）用灰色居中显示。
- 消息列表使用纯文本渲染，禁止 HTML/富文本和可点击链接，防止内容注入。
- 输入框限制 500 字符，回车或点击“发送”发送；空消息不发送。发送成功后清空输入框并滚动到底部。
- 聊天记录仅保存在内存中，创建/加入新房间或断开连接时清空，不写入磁盘。
- 断线后输入框禁用，消息列表保留至下次创建/加入房间。

### 7.5 中文文案

所有菜单、按钮、提示、错误信息使用简体中文。菜单结构：

- 对局：人机对战、创建局域网房间、加入局域网房间、退出。
- 帮助：规则说明、关于。

## 8. 错误处理与日志

- 端口占用、绑定失败、连接超时、连接被拒绝：弹窗提示具体原因，允许重试或改用其他端口。
- 协议错误、越权操作：记录日志并回复 `error`；不影响正常对局。
- 聊天消息为空、超过 500 字符或包含非法控制字符：主机丢弃并回复 `error`，不转发、不崩溃。
- AI 计算异常或超时：回退随机合法点，状态栏提示。
- 数子阶段无合法标记或数据异常：回到对局状态并提示。
- 日志输出到标准错误；关键网络事件同时显示在状态栏。

### 9.1 自动化测试

- `test_rules.py`：提子、多组提子、禁入点、普通劫、超级劫、pass、认输、悔棋、边界坐标。
- `test_scoring.py`：空盘、单方围空、死子标记、贴目 7.5、和棋场景。

- `test_ai.py`：AI 返回合法点、无合法点时 pass、时间上限内返回、9/13/19 路均可运行。

运行方式：`python3 -m unittest discover -s tests -v`。

### 9.2 手工验收

1. 人机模式在 9/13/19 路各完成一局，验证提子、pass、数子、悔棋、认输。
2. 同一台机器启动两个实例（`--no-discovery`），通过 `127.0.0.1:45679` 完成一局联机对战。
3. 两台同局域网机器通过自动发现和手动 IP 各完成一局。
4. 联机中验证越权落子被拒绝、断线提示、版本不一致提示。
5. 联机双方在对局和数子阶段互发聊天消息，验证显示、滚动、长度限制和断线后输入禁用。
6. 缩放窗口，确认棋盘与界面布局正常。
